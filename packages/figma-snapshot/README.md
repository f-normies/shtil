# figma-snapshot

Снимок макетов Figma в [`docs/design/figma/`](../../docs/design/figma/README.md) для работы без Figma MCP. Обновляет его тот, у кого есть место Full или Dev и подключён Figma MCP в Claude Code.

Устройство: агент вызывает инструменты Figma MCP, ответы ложатся в журнал сессии Claude Code (`~/.claude/projects/<проект>/<сессия>.jsonl` и журналы субагентов рядом). Скрипт `snapshot` читает журналы и пишет файлы. Код кадров попадает в репозиторий байт в байт, без пересказа моделью.

## Лимиты Figma MCP

Место Full на плане Professional — 10 вызовов в минуту и 200 в сутки ([документация](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/)). Полный снимок — около 190 вызовов `get_design_context` и `get_screenshot`. Вызывай их одним субагентом, не больше двух вызовов за сообщение. Несколько параллельных субагентов упираются в минутный лимит.

## Обновление

1. **Перечень кадров.** `use_figma` со скриптом [`figma/list-page.js`](figma/list-page.js) для страниц «Врач» (`109:15`), «Пациент» (`17:4`) и «Компоненты» (`17:2`), по одному вызову на страницу. Плюс `get_metadata` для `17:2`: из него берутся позиции вариантов в наборах.
2. **Текст аннотаций.** `use_figma` со скриптом [`figma/texts.js`](figma/texts.js) по id аннотаций из перечня, пачками: ответ `use_figma` — не больше 48 КБ. Нужны все аннотации страницы, включая «Как читать макет…» и «Подпись · …». Каких id не хватает, скажет шаг 7.
3. **Токены и иконки.** `use_figma` со скриптами [`figma/variables.js`](figma/variables.js) и [`figma/icons.js`](figma/icons.js).
4. **Кадры.** Для каждого кадра — `get_design_context` с `excludeScreenshot: true` и `get_screenshot` с `maxDimension`, равным длинной стороне кадра. Список кадров — [`docs/design/figma/frames.json`](../../docs/design/figma/frames.json). Если ответ разреженный (только XML без кода), вызови `get_design_context` для его дочерних узлов: скрипт соберёт их как части кадра.
5. **Сборка.** Перед первым запуском — `pnpm --dir packages/figma-snapshot exec playwright install chromium`.

   ```sh
   S=~/.claude/projects/<проект>/<сессия>
   pnpm --dir packages/figma-snapshot snapshot --sessions "$S.jsonl" --sessions "$S"
   ```

   `--sessions` можно повторять: выгрузка часто идёт в несколько сессий из-за суточного лимита. Если узел выгружен несколько раз, берётся самый новый ответ по времени в журнале.

6. **Недостающие иконки.** Если скрипт пишет «Ресурсов без SVG: N», выгрузи их: `use_figma` со скриптом [`figma/svgs.js`](figma/svgs.js) по id из `.cache/missing-assets.json`, пачками по 30. Затем повтори шаг 5. Узлы без видимых слоёв остаются пустыми: так и в макете.
7. **Проверка.** Скрипт пишет `.cache/missing.json`: кадры без кода или скриншота и id аннотаций без текста. Их выгрузи и повтори шаг 5. Таблицы в `docs/design/figma/*/README.md` показывают сходство клона с эталоном. Ниже 97 % — смотри `.cache/diff/<кадр>.diff.png` и `.clone.png`; такие кадры помечены в `notes.md` как неполные.
8. **Коммит** каталога `docs/design/figma/`.

Что происходит при повторном запуске:

- Файл перекачивается, только если его адрес сменился. Журнал скачиваний — `.cache/downloads.json`, без него перекачивается всё.
- Ресурсы, на которые код кадра больше не ссылается, удаляются. Каталоги кадров, которых больше нет в макете, удаляются тоже.
- Временные адреса Figma живут 7 дней. Если адрес истёк, файл остаётся прежним, а скрипт пишет об этом строкой с `!`. Поэтому собирай снимок не позже недели после вызовов.
- Ошибка одного кадра не обрывает снимок: кадр остаётся без клона, остальные собираются.

Клон собирается из кода, который вернул Figma MCP: при сборке он выполняется в Node. Источник кода — наш файл Figma, поэтому это допустимо, но код из чужих файлов так не собирай.

## Модули

| Файл | Что делает |
|---|---|
| `src/transcript.ts` | Ответы инструмента из журналов, включая вынесенные в файл. |
| `src/collect.ts` | Все ответы Figma MCP по узлам: код, скриншоты, перечни, тексты, SVG, переменные. |
| `src/manifest.ts`, `src/layout.ts` | Какие кадры клонировать, их каталоги латиницей, привязка аннотаций к экранам. |
| `src/sanitize.ts` | Поправки к коду MCP (список — в README снимка). |
| `src/materialize.ts`, `src/download.ts` | `reference.tsx`, ресурсы, скриншоты, заметки, иконки, токены. |
| `src/build.ts`, `src/page.ts`, `src/variants.ts` | Клон `index.html`: React на сервере, Tailwind CLI по коду кадра, наборы вариантов. |
| `src/compare.ts` | Попиксельная сверка клона с эталоном в Chromium. |
| `src/docs.ts`, `src/gallery.ts`, `src/tokens.ts`, `src/notes.ts` | Markdown, галерея, CSS токенов. |
| `src/report.ts` | Удаление лишних каталогов, отчёт о пропусках, пометка неполных клонов. |
| `src/snapshot.ts` | Команда `snapshot`: все шаги по порядку. |
